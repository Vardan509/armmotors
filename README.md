# ArmMotors — Node.js / MongoDB

Կայքի ապրանքները, գրանցումները, նախընտրելիները, գնման հայտերը, հաղորդագրությունները և ադմինի գործողությունները պահպանվում են MongoDB-ում։ Ստատիկ ցուցադրական ապրանքներ այլևս չեն ցուցադրվում։ Դատարկ բազայի դեպքում ապրանք ավելացրեք ադմինից կամ հայտարարության էջից։

## Գործարկում

Պահանջվում է Node.js 22+ և MongoDB 5.0+ (տեղական կամ Atlas)։

1. `backend/.env.example`-ի հիման վրա լրացրեք `backend/.env`։ Գոյություն ունեցող .env-ը պահպանված է, ավելացված դաշտերը դատարկ են։ JWT_SECRET-ը պետք է լինի պատահական, առնվազն 32 նիշ։
2. `backend` թղթապանակում՝ `npm install`, ապա `npm run dev` (production-ում՝ `npm start`)։
3. `frontend` թղթապանակում՝ `npm install`, ապա `npm run dev`։ Vite-ի `/api` proxy-ն կապվում է backend-ի 3001 պորտին։ Առանձին hosting-ի համար սահմանեք `VITE_API_URL` և backend-ի `CLIENT_ORIGIN`-ը։

## Ադմին

Լրացրեք `ADMIN_EMAIL` և առնվազն 12 նիշանոց `ADMIN_PASSWORD`, ապա backend թղթապանակում աշխատեցրեք `npm run admin:create`։ Այն գաղտնաբառը hash է անում և ստեղծում role=admin հաշիվ։ Գործարկումից հետո ADMIN_PASSWORD-ը կարող եք հեռացնել .env-ից։ Գոյություն ունեցող հաշվի դերը փոխելու համար՝ `npm run admin:create -- --promote` (գաղտնաբառը չի փոխվում)։

Մուտք գործելուց հետո բացեք `/admin`։ Հասանելի են՝ օր/շաբաթ/ամիս վաճառքի dashboard, ապրանքների ստեղծում/փոփոխում/ջնջում, draft/active/sold վիճակ, օգտատերերի որոնում, ban/unban/հաշվի ջնջում, գնման հայտեր, հաղորդագրություններ, broadcast և գործողությունների պատմություն։ Ադմինի իրավունքները ստուգվում են սերվերում։ Ban/unban/ելքը անվավեր են դարձնում գործող token-ները, իսկ ադմինի հաշիվը պաշտպանված է այս կառավարման գործողություններից։

## Գնման հայտեր

Ապրանքի էջից գնման հայտը պահպանվում է սերվերի ընթացիկ AMD գնով։ Օգտատերը հետևում է `/account` էջում և կարող է չեղարկել սպասող հայտը։ Գործարքն ու վճարումը ստուգելուց հետո ադմինը հաստատում է գնումը։ Միայն հաստատված գնումներն են մտնում վաճառքի հաշվետվություն, ապրանքը դառնում է sold, մյուս սպասող հայտերը չեղարկվում են։ Սա բանկային վճարում չի կատարում. վճարային մատակարար դեռ միացված չէ։ Ավարտված գնումների գումարի snapshot-ը պահպանվում է նաև ապրանքը կամ օգտատիրոջը ջնջելուց հետո։

## Google գրանցում / մուտք

Google Cloud Console-ում ստեղծեք Web application OAuth client ID և այն դրեք `GOOGLE_CLIENT_ID`-ում։ Authorized JavaScript origins՝ `http://localhost:5173`, `http://127.0.0.1:5173` և production-ի ճշգրիտ HTTPS origin-ը։ Այս Google Identity Services ID-token հոսքին client secret անհրաժեշտ չէ և այն frontend-ում չպետք է հայտնվի։ Սերվերը Google-ի պաշտոնական գրադարանով ստուգում է ստորագրությունը, audience-ը և հաստատված email-ը։ Գոյություն ունեցող գաղտնաբառով հաշիվը Google-ին կապեք `/account`-ից՝ նույն email-ով, ավտոմատ account linking չի կատարվում։

Պաշտոնական ուղեցույցներ՝ https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid և https://developers.google.com/identity/gsi/web/guides/verify-google-id-token ։ Իրական Google մուտքը պահանջում է Ձեր client ID-ի կարգավորումը։

## Broadcast email

Լրացրեք `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE` (`true`՝ սովորաբար 465, `false`՝ 587), `SMTP_USER`, `SMTP_PASS`, `EMAIL_FROM`։ Ավելի վաղ EMAIL_USER/EMAIL_PASS Gmail տարբերակն էլ աջակցվում է։ Gmail-ի դեպքում օգտագործեք app password։

`/admin/broadcasts`՝ ստեղծեք վերնագիր և նամակ, տեսեք HTML նախադիտումը, պահեք draft-ը, ապա առանձին հաստատեք ուղարկումը։ Յուրաքանչյուր ակտիվ գրանցված օգտատեր ստանում է առանձին նամակ՝ մյուսների email-ները չտեսնելով։ Արգելափակված կամ ջնջված հաշիվները բաց են թողնվում։ Հերթը պահվում է MongoDB-ում, worker-ը գործում է backend-ի հետ, մեկ նամակ յուրաքանչյուր BROADCAST_INTERVAL_MS ժամանակահատվածում (լռելյայն՝ 3000ms)։ SMTP-ն պետք է թույլ տա ընտրված ծավալը։

Կարգավիճակներ՝ pending/sending/sent/failed/uncertain/skipped։ Timeout-ի կամ ընդհատման դեպքում uncertain նամակը ավտոմատ կրկին չի ուղարկվում՝ կրկնօրինակներից խուսափելու համար։ Անավարտ հերթի չեղարկումը չի վերադարձնում արդեն ուղարկված նամակները։ Draft/առաքումների պատմությունը տեսանելի է ադմինում։ Այս աշխատանքի ընթացքում իրական հասցեներին broadcast չի ուղարկվել։

## Ստուգումներ

Backend՝ `npm test`։ Թեստերը նույն MongoDB կապի վրա ստեղծում են առանձին `armmotors_test_<timestamp>_<pid>` բազա և ավարտին հեռացնում միայն այդ բազան։ Թեստային SMTP-ն JSON transport է, արտաքին նամակ չի ուղարկում։ Frontend՝ `npm run lint`, `npm run build`։

Հյուրի սրտիկները պահվում են browser-ում։ Մուտքից հետո իրական ապրանքների ընտրությունը տեղափոխվում է հաշվի MongoDB favorites բաժին։ Արժույթի ընտրությունը ցուցադրական փոխարկում է. պատվերների պահվող գումարները AMD են։
